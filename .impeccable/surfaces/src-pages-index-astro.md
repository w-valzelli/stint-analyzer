# Analyzer surface brief

- **Mode:** Operate
- **Audience:** Drivers and coaches in a post-session debrief.
- **Job:** Compare selected drivers and stints, understand the runtime gap, and trace important numbers to source laps.
- **First proof:** The first screen shows source facts, import state, counts, and the detected-lap table without decorative product language.
- **Constraints:** Preserve local-only analysis, clear scope controls, separate runtime from pace, runtime-only standings, factual invalid-lap counts, and lap-level auditability. Do not infer penalties from Clean. Keep Garage 61 as the source format, not the site brand. Avoid meaningless identifiers and privacy-first header chrome.
- **Chosen direction:** Working Record. Use mineral paper, ruled data, a subtle source-card registration texture, compact state icons, and short analysis-panel color marks. Make the interface direct without making it generic.
- **Memorable moment:** A user removes one imported source file and sees the counts and detected drivers update without losing the remaining files.
- **Unresolved decisions:** Data-rich analysis states and the import workflow remain open until later milestones. The visual language, type pairing, and responsive breakpoints are established in the built shell and `DESIGN.md`.
